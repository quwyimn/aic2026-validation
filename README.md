# Validation — AI City Challenge 2026, Track 1

Quality-control stage for the Track 1 model. Takes the model's output files, compares them against ground truth, reports whether object classes are correct — and if not, which pipeline stage is at fault.

Scope: **validation only**. This project does not train, does not modify the model. See `docs/roadmap_validate.md` for the full plan.

## Folders

### `config/`
Single source of truth for every tunable value: paths, IoU threshold, 3D distance threshold, the official class_id table. Nothing hardcoded anywhere else — one file to change, one place to look when a number seems wrong.

### `docs/`
Planning and reference documents. Holds the roadmap and the handoff format agreed with the training stage.

### `data/`
All input data. Nothing here is generated by `src/` except `synthetic/`.

- **`gt/`** — ground truth downloaded from the organizers (val split: W020, W021). The answer key. Read-only; never edited.
- **`input/`** — `track1.txt` (File A) and `detections_2d.txt` (File B) received from the training stage. One subfolder per model version so results stay comparable across runs.
- **`synthetic/`** — fake File A / File B generated from the GT with deliberately injected errors. Used to prove the validator itself works.

### `src/`
Library code. No entry points here — everything is importable, nothing runs on import.

- **`io/`** — reading and parsing. GT loader with schema auto-detection (W008+ uses abbreviated field names: `type`, `loc3d`, `bbox3d`, `rot3d`), File A parser, File B parser. Format validation lives here: wrong column count, out-of-range class_id, and unit anomalies are caught at load time, not three stages later.
- **`matching/`** — pairing predictions to GT. 2D IoU, 3D Euclidean distance, Hungarian assignment. **All matching here is class-blind by design** — matching on geometry alone is what makes misclassification visible instead of hiding it as a miss + ghost pair.
- **`metrics/`** — turning matched pairs into numbers. Confusion matrix (with miss/ghost rows and columns), precision, recall, per-class GT counts.
- **`layers/`** — the two validation layers. `layer_2d.py` measures File B against 2D GT (does the model recognize the object?). `layer_3d.py` measures File A against 3D GT (after fuse/track/remap, is the class still right?). Both are thin: they wire `io` → `matching` → `metrics` together.
- **`synth/`** — error injection. Generates the contents of `data/synthetic/`: class swaps, position shifts, deletions, phantom objects, whole-table class shifts, track fragmentation. Every injected error is logged so the test suite knows the expected answer.
- **`diagnose/`** — cross-references the two layers and produces the verdict: model error / pipeline error / mapping error. This is the part that answers *where* the problem is, not just *that* there is one.

### `scripts/`
Command-line entry points. Thin wrappers over `src/` — argument parsing and orchestration only, no logic.

- `inspect_gt.py` — print the class list, per-class object counts, and detected schema of a GT file. First thing to run after downloading data.
- `make_synthetic.py` — build the synthetic dataset with injected errors.
- `run_validation.py` — run both layers plus diagnosis, write a report.

### `reports/`
Run output, one folder per run: metrics as JSON (machine-readable, for the dashboard and for diffing across versions) and as CSV/Markdown (human-readable). Never overwritten — comparing version N against N-1 is the point.

### `dashboard/`
Streamlit app. Reads from `reports/`, computes nothing itself. Shows both confusion matrices side by side, the per-class table, the verdict, and a BEV map of where misclassified objects sit in the warehouse. Runs locally.

### `tests/`
Verification of the validator itself. Runs validation against `data/synthetic/` and asserts that the reported errors match the injected ones exactly. A validator that has never been verified produces numbers that are just made up — this folder is what makes the output trustworthy.

## Flow

```
data/gt/  ──┬──────────────────────────────► src/layers ──► reports/ ──► dashboard/
            │                                    ▲                          
            └──► src/synth ──► data/synthetic ───┤                          
                                                 │              
data/input/ (from training stage) ───────────────┘              
```

Ground truth feeds both the real run and the synthetic run. The synthetic path is what `tests/` uses to prove the layers are correct before the real files ever arrive.
