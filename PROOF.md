# PROOF — that the validator is correct

*This document has one purpose: to prove the validator is correct, with evidence
anyone can reproduce, not with assertions. Every claim comes with how a sceptic
checks it — and with the boundary of what it establishes, because a proof that
overclaims is easier to dismiss than one that is careful.*

---

## The claim

> The validator assigns the correct diagnosis — MODEL / MAPPING / PIPELINE /
> CLEAN — **and** its file format / class_id / frame indexing / coordinate and
> yaw conventions match the organizers, meaning a submission that passes through
> it will be scored by the official evaluator exactly as the validator predicts.

The core difficulty is a loop: the fixtures used to test the validator are
generated by the team, from that same GT, by code that shares the validator's
assumptions. If the generator and the measurer misread the same thing, the tests
still pass and both are wrong. **A proof is breaking that loop.**

---

## Top-tier evidence: the official scorer agrees

This is the one layer that never passes through the team's hands. NVIDIA's HOTA
scorer (`spatialai-data-utils`, `evaluate_aicity_mtmc.py`) parses on its own,
checks class_id on its own, matches by 3D IoU on its own, computes the metric on
its own. Run it on the team's own fixtures:

| Fixture | Validator's diagnosis | Official HOTA | Match? |
|---|---|---|---|
| `clean` | CLEAN (both layers 1.000) | **HOTA = 100.00** (Forklift/PalletTruck/Person all 100; DetA/AssA/LocA = 100/100/99.9997) | ✅ |
| `mapping_shift` | MAPPING (2D clean, 3D uniformly shifted) | **HOTA = 0.0096** | ✅ |

Both results were **predicted before the run**. A correct prediction is more
convincing than a measurement, because a measurement can be a coincidence and a
correct prediction cannot.

### What `clean = 100.00` proves — and what it does NOT

**Proves:** the official scorer **accepts** the file (11 columns, valid
class_ids, in-range frames — had any been wrong, its parser would have thrown
rather than scoring), **and** the converter and the generator are in **total
agreement** on every box value under the scorer's column reading (had a single
column been off, IoU could not have reached 1).

**Does NOT on its own prove:** that the column order / yaw axis match the
*organizers*. Bluntly: if the converter **and** the generator both transpose the
same pair of columns (e.g. w↔l), or both misread the yaw axis, the two boxes
still coincide, IoU is still 1, `clean` is still 100 — wrong, but invisibly.
`clean = 100` measures **three-way consistency**, not absolute correctness by
itself.

Absolute correctness rests on a **second, independent leg** — reading the
scorer's own code directly, not inferred from a score:

| Silent killer | Established by (documentary) |
|---|---|
| Order of the 11 columns | `aicity_mtmc_eval.py:302–313` — the parser's field order, read directly |
| class_id, the 7-class table, PalletTruck=6 | `datasets/aicity26/spec.py` |
| yaw about the z-axis (not y, as the submission spec text says) | rotation-matrix code in `_base_dataset.py`, composing `Rz @ Ry @ Rx` |
| frame 0-based, meters, radians | hard-validated in `split_aicity_mtmc_per_scene_per_class` |

**Both legs standing is what makes it a proof:** `clean = 100` (consistency +
accepted by the scorer) **plus** the code read (column order + yaw axis match the
organizers). Remove either leg and there is a gap. The one residual — a column
transposition that the converter and generator *both* make *and* that also
happens to align with the parser order that was read — only closes fully at
**Step 8**, when the training stage's independently-written file is scored on this
same GT-txt and comes out sensible. Stated here so no one thinks the loop is 100%
broken.

### Why `mapping_shift ≈ 0` matches the mechanism, not just the number

```
Forklift:    HOTA=0.02   (receives objects shifted in from another class)
NovaCarter:  skipping (missing GT)     ← absent from the scene, but shifted into
PalletTruck: skipping (missing pred)   ← every PalletTruck was shifted to Person
Person:      HOTA=0.00   (every Person became a Forklift)
```
This is exactly the signature of the permutation `c → (c+1) mod 7`: every
(scene, class) pair is missing either GT or pred → skipped or ≈ 0. HOTA is
**0.0096, not a flat 0** — a few pairs slip through where 3D IoU happens to match
across classes, exactly as the "near zero" prediction expected. And
`PalletTruck: skipping (missing pred)` confirms, with the naked eye, the
drop-a-pair-that-is-missing-one-side rule at `aicity_mtmc_eval.py:695–702`.

**Reproduce:**
```bash
python3 scripts/gt_to_txt.py --scene Warehouse_020 \
    --self-check data/synthetic/Warehouse_020/clean/track1.txt   # must print MATCH
REPO=video-search-and-summarization/libs/analytics/spatialai-data-utils
python3 $REPO/tools/evaluation/evaluate_aicity_mtmc.py \
    --ground_truth_file data/gt_txt/Warehouse_020/ground_truth.txt \
    --input_file        data/synthetic/Warehouse_020/clean/track1.txt \
    --scene_id_2_scene_name_file scene_map.json \
    --output_dir /tmp/hota_clean --num_frames_to_eval 9000 --quiet
```

## The converter is correct at full scale (narrowing the last gap)

The scorer is independent, but the converter `gt_to_txt.py` is the team's own
code. It is checked separately: `clean/track1.txt` is generated from this very
GT, so GT-txt and pred must share every key.

```
GT rows (keys):   610776
pred rows (keys): 610776
in GT not pred:   0
in pred not GT:   0
MATCH
```

610,776 = the exact File A row count. 0 mismatches on either side, at **full 9000
frames**. Converter and generator agree perfectly on (scene, class, id, frame).
Combined with `clean = 100` (which forces the box *values* to match too, not just
the keys) and the read of the scorer's code (which forces the *column order to be
the organizers'*), the whole converter path is proven down to the residual noted
above.

Before any external scorer, the validator is shown to reproduce every injected
error, on both warehouse families, at full 9000 frames:

- **W020 (family A): 12/12.** **W011 (family B): 12/12.** Total **24/24**.
- `mapping_shift` discriminates the two families correctly: W020 flags **3**

- `dup_id` produces collisions at the right scale: W020 = 29,907, W011 = 18,000

Note the level of evidence: 24/24 proves the validator is **self-consistent** —
necessary but not sufficient, because the fixtures and the validator both come
from the team. It becomes a full proof only once the external layer above agrees.

## The blind spot, acknowledged and measurable

A proof does not mean "no limits". The validator matches on centre distance, so
it is **blind to wrong box size and wrong heading**. This is:
- **Acknowledged** in the report: `wl_swap` prints `PASS [BLIND SPOT]`, not a
  bare PASS.
- **Guarded by a test:** if the 3D layer is upgraded to see shape, the `wl_swap`
  fixture flips to FAIL, forcing the expectation to be updated. Verified by
  simulating the upgraded layer.
- **Distinguished from `yaw_pi`:** yaw_pi is also CLEAN, but for a different
  reason — a rectangular box is symmetric under a 180° turn, so the official
  metric *also* awards zero penalty. That is a rule of the game, not a tool
  limitation, and it prints `PASS [ZERO-IMPACT]`.

The magnitude of the `wl_swap` blind spot depends on the edge-ratio distribution
of each class in the real scene, so it can only be measured by running HOTA on
`wl_swap` over W020 — see "what remains".

## Self-scrutiny: the validator was wrong 6 times

That the validator has been caught in error several times is evidence it was
examined closely, not green from the start. Each error has a number:

1. Zero-area GT boxes — `clean` scored 0.948 instead of 1.000.
2. False positives on absent classes — 73,549 hidden behind a precision of 1.000.
3. `mapping_shift` demanded 6 flags from a scene with only 3 classes → false FAIL.
4. `position_shift` demanded exactly zero confusion — 56/48,000 was correct.
5. `phantom` misdiagnosed as PIPELINE because 894 ghosts fell under the threshold.
6. The dashboard confusion matrix dropped the column of a class with no GT.

The lesson, three times over: **errors only appear at full 9000 frames** — so
everything is verified at full scale.
